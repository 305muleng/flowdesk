# 后端状态映射

Java 实体和业务判断使用领域枚举，数据库、接口和操作日志继续使用原有字符串。
项目状态、任务状态、各类审批状态、用户状态及成员状态分别定义，不能因为名称相同而合并。

## 编码约定

状态使用普通 Java 枚举，名称就是数据库及接口编码。
getCode 返回 name，供接口和日志使用；fromCode 对 null 返回 null，其他值通过 valueOf 严格转换。
空串、大小写错误和未知名称会报错，不自动修正或回填。

数据库使用当前 MyBatis-Plus 默认的普通枚举名称映射；MybatisPlusConfig 仅保留分页配置。
JSON 通过 JsonValue/JsonCreator 明确使用同一字符串约定，数据库映射与 JSON 映射分别验证。
枚举名称属于持久化和接口契约，不能按普通变量随意重命名。

## 保留的边界

- ALL 是查询筛选选项，EXPIRED 是展示时计算的状态，不作为实体状态写入。
- 聚合结果、VO、请求筛选和日志载荷仍保留字符串，各自在业务边界转换或校验。
- 系统角色、项目角色、审核动作和优先级的实体字段仍是字符串，辅助枚举集中定义合法值；这不等于实体已获得枚举类型约束。
- TaskReminderKind 的通知类型和标题是不同于名称的业务元数据，继续保留对应字段。
- 枚举不能替代权限、状态迁移校验、事务、锁和条件更新，也不能约束绕过应用直接写入的 SQL。

## 验证

StatusCodeMappingTest 检查实际 MyBatis 参数绑定和结果映射，包括合法值、NULL、非法值及动态条件。
StatusJsonCompatibilityTest 检查原有 JSON 编码和筛选错误。
真实数据库及 HTTP 回归分别验证实体读取、状态推进、鉴权和接口兼容，不能用 JDBC 替身结果代替。
