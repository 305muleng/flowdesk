# FlowDesk

FlowDesk 是一个以研发团队协作为背景的项目、任务与交付验收系统，覆盖项目创建、成员协作、任务执行、成果审核、项目验收与归档。

项目用于 Java 后端工程实践和实习、校招准备，重点展示业务建模、权限控制、事务并发、缓存一致性、异常处理和测试能力。

## 业务流程

```text
创建项目
  → 邀请成员、规划任务
  → 启动项目
  → 执行任务、提交成果
  → 项目负责人审核
  → 提交项目验收
  → 系统管理员审核
  → 完成并归档
```

项目验收被驳回后，可以继续整改并再次提交。成员退出、负责人转让、站内通知和操作审计为主流程提供支持。

## 角色与权限

系统角色和项目角色分开管理。

| 角色 | 职责 |
| --- | --- |
| 普通用户 `USER` | 创建项目、接受邀请，在不同项目承担不同职责 |
| 系统管理员 `SYSTEM_ADMIN` | 管理账号、审核项目验收，不自动拥有普通项目管理权限 |
| 项目负责人 `PROJECT_MANAGER` | 管理本项目成员、任务、审批、交付及生命周期 |
| 开发人员 `DEVELOPER` | 执行任务、提出任务申请、参与讨论和申请退出 |

项目角色属于用户与项目之间的关系。同一个用户可以是一个项目的负责人，同时是另一个项目的开发人员。

后端根据当前账号和项目成员关系校验权限。前端菜单和按钮用于引导操作，不代替后端鉴权。

## 主要功能

### 项目管理

- 创建项目，创建者自动成为项目负责人。
- 查看参与项目、项目详情、成员及操作记录。
- 启动、取消、提交验收和归档。
- 项目取消后冻结正常推进，但不批量修改正式任务状态。

项目状态：

```text
PREPARING → IN_PROGRESS → PENDING_ACCEPTANCE → COMPLETED → ARCHIVED
                              │
                              └─验收驳回→ IN_PROGRESS

PREPARING / IN_PROGRESS → CANCELLED
```

待验收期间暂停日常修改，完成、归档和取消后限制业务写操作。

### 任务与任务申请

- 项目负责人创建正式任务，设置任务负责人、优先级和截止时间。
- 开发人员提出任务申请，负责人批准后生成正式任务。
- 任务支持开始、提交、审核、取消、评论和提交历史查询。
- TODO 状态允许重新分配任务负责人。
- 项目负责人也可以承担任务，当前允许其审核自己提交的成果。

任务状态：

```text
TODO → IN_PROGRESS → REVIEW → DONE
                       │
                       └─驳回→ IN_PROGRESS

TODO / IN_PROGRESS → CANCELLED
```

审核驳回时，如果原任务负责人账号已不可用，任务回到 TODO 并清空负责人，等待重新分配。

### 成员管理

- 邀请普通用户加入项目，支持接受、拒绝和过期判断。
- 开发人员申请退出，由项目负责人审批。
- 项目负责人可以移除符合条件的开发人员。
- 负责人转让需要密码确认，并由目标用户接受。
- 转让时，原项目负责人可以留任开发人员或退出项目。

退出或移除成员前检查未完成任务。成员关系停用后保留历史任务归属和贡献，不直接删除历史关系。

### 账号禁用与任务交接

- 管理员可启用或禁用账号。
- 仍负责特定状态项目的账号不能直接禁用，页面按项目说明转让、验收处理或归档要求。
- 禁用不自动删除成员关系，也不自动重新分配任务。
- 禁用提交后，向相关活动项目的负责人尽力发送站内通知。
- 项目成员页可定位禁用成员承担的未完成任务。
- 对禁用账号承担的 IN_PROGRESS 任务，项目负责人可以填写原因，交接给有效项目成员。
- 交接后任务回到 TODO，保留内容、评论和提交历史，并记录审计。
- 重新启用账号不会自动撤销已经完成的交接。

通知失败不会回滚已提交的禁用操作。当前没有持久化通知重试或通知必达保障。

### 项目交付与验收

提交验收前要求：

- 项目处于 IN_PROGRESS。
- 没有 TODO、IN_PROGRESS、REVIEW 任务。
- 没有 PENDING 任务申请。
- 提供验收说明及至少一个代码仓库、部署或文档链接。

管理员通过后项目进入 COMPLETED；驳回后回到 IN_PROGRESS，整改后生成新一轮验收记录。

当前不单独禁止零任务或全部任务取消的项目提交验收，由其他条件和管理员审阅共同约束。

验收详情包含本轮提交及审核记录；新提交展示该轮保存的项目资料、交付链接、任务统计、取消任务和成员贡献，旧记录按下述兼容规则展示。

新提交的验收记录保存独立的V1提交快照，包含项目资料、交付链接、任务统计、成员贡献及取消任务清单。驳回整改后重新提交会新增记录，历史轮次仍显示各自提交时的数据。当前项目状态和本轮审核结果继续正常更新。

旧记录的两个快照字段均为NULL时，详情明确标注“未保存提交快照，展示当前数据”，不回填伪造历史。快照内容损坏或版本不支持时返回明确错误，不用当前数据替代。完整详情仍仅管理员可读，普通成员权限不变。外链内容本身没有归档。

已有数据库运行本版本前，需先在选定数据库执行 `database/migrations/20261023_add_acceptance_snapshot.sql`，新增两个可空字段；完整建表文件已包含这两个字段。迁移应先在测试库验证，业务库执行需要单独确认。勿将原始完整schema作为已有数据库的增量迁移使用。

### 两种统计口径

| 指标 | 公式 | 含义 |
| --- | --- | --- |
| 执行进度 | `DONE / (总任务数 - CANCELLED) × 100%` | 有效工作范围完成了多少 |
| 验收完成占比 | `DONE / (DONE + CANCELLED) × 100%` | 已结束任务中，完成而非取消的比例 |

分母为零时均返回 0。

例如 8 个任务完成、2 个取消，执行进度为 100%，验收完成占比为 80%。后者不是管理员审批通过率。

### 请求关闭与过期

- 验收通过：关闭仍有效的待处理邀请、退出申请和负责人转让。
- 项目取消：额外关闭待处理任务申请。
- 关闭使用 `CLOSED`，保存关闭时间和原因。
- 已处理或已过期记录不被覆盖。
- 待验收期间只暂停操作；驳回后，未过期且符合条件的请求可以继续处理。
- 项目结束与请求关闭位于同一事务。
- 不追溯关闭以前已结束项目的遗留请求。

查询时识别过期，操作时重新检查有效期。CLOSED、用户撤回、拒绝和时间过期具有不同含义。

### 分页、筛选与统计

项目任务、我的任务和通知列表使用后端分页：

- 默认每页 20 条，最多 100 条。
- 筛选在分页前执行，总数对应完整筛选结果。
- 项目任务支持范围、状态、任务负责人及仅未完成筛选。
- 我的任务支持状态和标题关键词筛选。
- 通知支持分类及已读筛选。
- 相同时间使用 ID 作为第二排序条件。
- 筛选变化重置页码，数据减少后处理空页回退。

项目进度使用项目汇总接口，个人统计使用当前用户汇总接口，不从当前页计算全量统计。

通知未读总数与“全部已读”覆盖当前用户的全部通知，不受当前页或分类限制。

### 通知与审计

站内通知关联邀请、申请、任务、验收及成员事件，支持已读处理和历史跳转。

已读不表示关联业务已经处理。历史记录能否查看、能否操作，仍由对应业务权限和状态决定。

操作审计保存操作者、对象、动作、修改前后信息和时间，用于追踪关键业务变化。

## 后端设计

### 认证与权限

- BCrypt 保存密码哈希。
- JWT 标识登录用户。
- 请求拦截器读取当前账号状态及系统角色。
- Service 根据当前项目成员关系校验业务权限。
- 请求结束后清理 ThreadLocal 用户上下文。

退出登录当前清除客户端凭证，不提供服务端 Token 黑名单或会话吊销机制。

### 事务与并发控制

关键状态变化结合数据库事务、项目行锁和条件更新，协调任务写入、成员变更及项目验收。

条件更新检查预期状态或负责人，避免过期请求直接覆盖已经变化的业务结果。

请求关闭使用 MANDATORY 参与项目结束事务；禁用通知使用提交后本地事务事件，并以独立事务隔离各项目通知失败。

这些机制有不同的业务目的，不代表已经实现所有故障场景下的可靠投递或分布式事务。

### Redis 任务统计缓存

接口：

```text
GET /projects/{projectId}/task-summary
```

设计：

- 先校验项目权限和存在性，再读取缓存。
- Key：`flowdesk:project:{projectId}:task-summary:v1`。
- Value：任务统计 JSON，TTL 为 60 秒。
- 未命中时查询数据库并回填。
- Redis 读取失败时回退数据库，跳过本次回填。
- 影响统计的业务提交后删除缓存，回滚不删除。
- 使用延迟补删降低旧值回填的影响。

配置项：

```properties
flowdesk.cache.task-summary.second-delete-delay-ms=10000
```

当前 10 秒为实验配置，不是已论证的生产参数。

延迟补删不保证强一致；删除失败、进程退出、调度拒绝和更晚的旧值回填仍是边界。当前没有可靠补偿队列或跨请求熔断。

个人任务汇总接口为：

```text
GET /tasks/my/summary
```

只统计当前登录用户有权访问的任务，本接口当前不增加 Redis 缓存。

### 数据库初始化

结构文件：

```text
database/flowdesk-schema-20261018.sql
```

包含当前 13 张表和索引，包括任务统计覆盖索引及请求关闭字段，不包含业务数据。

**仅导入已选中的空数据库。当前已有结构的数据库不要重复执行，不把此文件用作升级脚本。**

若使用名为 mysql 的 Docker 容器，可以：

```bat
docker cp database/flowdesk-schema-20261018.sql mysql:/tmp/flowdesk-schema.sql
docker exec -it mysql mysql -u root -p
```

在 MySQL 客户端中创建并选择数据库：

```sql
CREATE DATABASE flowdesk
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_0900_ai_ci;

USE flowdesk;
```

然后在同一个 MySQL 命令行客户端中导入结构：

```text
SOURCE /tmp/flowdesk-schema.sql;
```

如果数据库已存在，先确认用途及内容，不直接继续导入。

使用本机 MySQL 时，不需要执行上述容器命令。由环境维护者创建并确认空数据库后，可在项目根目录导入结构，例如：

```bat
mysql -h 127.0.0.1 -P 3306 -u root -p flowdesk < database/flowdesk-schema-20261018.sql
```

命令仅用于初始化已确认的空库；已有数据库仍应使用对应增量迁移脚本。

注册接口只创建普通用户。首次系统管理员账号需要由环境维护者单独准备，项目不内置默认管理员密码。可先通过注册接口创建一个专用账号，在其尚未创建或加入普通项目时，由维护者核实账号身份后将系统角色设置为 `SYSTEM_ADMIN`。不要复用普通项目成员账号。

## 测试与实践记录

测试明确分为两层，避免普通检查依赖本机 MySQL/Redis，也避免把模拟测试称为真实数据库验证。

### 默认测试：不连接外部服务

在项目根目录运行：

```bat
mvnw.cmd test
```

默认只运行没有 `integration` 标签的测试，不需要数据库密码、Redis或应用密钥。包括业务判断、Web接口模拟、序列化、SQL契约及使用事务替身的测试；不能据此声称真实SQL、InnoDB锁或Redis已验证。

### 真实 MySQL/Redis 集成测试：显式启用

先准备专用测试环境并提供以下变量，不把实际凭据提交到仓库：

| 环境变量 | 用途 |
| --- | --- |
| `FLOWDESK_TEST_DB_PASSWORD` | 必填，专用测试数据库账号密码 |
| `FLOWDESK_TEST_REDIS_CONFIRMED` | 必须显式设为 `true`，表示已确认测试目标 |
| `FLOWDESK_TEST_REDIS_HOST` | 默认 `127.0.0.1`，仅允许 `127.0.0.1` 或 `localhost` |
| `FLOWDESK_TEST_REDIS_PORT` | 默认 `6379`，必须为有效端口 |
| `FLOWDESK_TEST_REDIS_DATABASE` | 默认 `15`，保护逻辑只允许DB15 |
| `FLOWDESK_TEST_REDIS_USERNAME` | 可选Redis认证用户名 |
| `FLOWDESK_TEST_REDIS_PASSWORD` | 可选Redis认证密码，按测试服务器实际配置提供 |

数据库固定为本地3306端口的 `flowdesk_test`，账号为 `flowdesk_test_user`，不能使用业务库或root账号。测试库应预先具备当前完整schema；已有结构按所需增量升级，测试命令不会自动建表或迁移。

确认环境后执行：

```bat
set "FLOWDESK_TEST_REDIS_CONFIRMED=true"
mvnw.cmd -Pintegration test
```

此profile只运行标有 `@IntegrationTest` 的真实集成测试，普通测试仍需执行前一条命令。未启用profile时，集成测试被过滤而非已通过；启用后缺少环境确认或目标不符则明确失败，不静默跳过。

单独运行其中一类时仍需启用profile，例如：

```bat
mvnw.cmd -Pintegration -Dtest=FlowdeskApplicationTests test
```

保护分两步：刷新测试上下文前核对配置；用例准备数据前核对实际数据库名/账号，以及Redis连接实际选择DB15。测试只清理自身专用记录和精确Key，不执行FLUSHDB/FLUSHALL，不启停服务。执行真实集成测试期间避免其他程序同时写入测试库，以便判定残留。

测试专用配置使用 `@TestConfiguration`，在专门的测试中显式加载，不通过允许任意Bean覆盖来绕过装配问题。完整应用上下文测试同时核对没有加载专用测试配置、事务替身或替换版服务。
